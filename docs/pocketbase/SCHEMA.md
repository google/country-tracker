# PocketBase Schema Definition

This file documents the required collections and fields for running the Country Tracker application using PocketBase as the backend.

## Collections

### 1. `users`
Stores user profile information and privacy settings.

- **Fields**:
  - `id`: Autogenerated by PocketBase (String).
  - `email`: String (Required, Unique).
  - `displayName`: String (Optional).
  - `photoURL`: URL string (Optional).
  - `visitedCountries`: JSON array of strings (e.g., `["US", "CA"]`). Default: `[]`.
  - `privacy`: JSON object. Default: `{"profileVisibility": "public", "globalLeaderboard": "public"}`.
  - `createdAt`: DateTime.

### 2. `groups`
Stores travel group metadata.

- **Fields**:
  - `id`: Autogenerated by PocketBase.
  - `name`: String (Required).
  - `searchName`: String (Required, lowercase version of name for searching).
  - `description`: String (Optional).
  - `ownerId`: Relation to `users` (Required).
  - `visibility`: String ('public' | 'private'). Default: `'private'`.
  - `memberCount`: Number. Default: `1`.
  - `createdAt`: DateTime.

### 3. `group_members`
Junction collection mapping users to groups with specific roles.

- **Fields**:
  - `id`: Autogenerated by PocketBase (or composite string like `groupId_userId` if supported, but standard relation is preferred).
  - `groupId`: Relation to `groups` (Required, Cascade delete recommended).
  - `userId`: Relation to `users` (Required, Cascade delete recommended).
  - `role`: String ('owner' | 'admin' | 'member'). Default: `'member'`.
  - `leaderboardVisibility`: String ('public' | 'anonymous' | null). Default: `null` (inherits from global).
  - `joinedAt`: DateTime.

> [!NOTE]
> Ensure a unique index is created on the combination of `groupId` and `userId` to prevent duplicate memberships.

### 4. `friends`
Stores bidirectional friendship requests and connections.

- **Fields**:
  - `id`: Autogenerated by PocketBase.
  - `requesterId`: Relation to `users` (Required).
  - `receiverId`: Relation to `users` (Required).
  - `status`: String ('pending' | 'accepted'). Default: `'pending'`.
  - `createdAt`: DateTime.

> [!NOTE]
> Ensure application logic handles preventing double requests by checking both directions, as PocketBase compound unique constraints might not cover switching order easily without custom hooks.

## Recommended API Rules (Security)

By default, PocketBase collections are private. To secure the application, you must configure the following API Rules in the PocketBase Admin UI for each collection.

### 1. `users`
-   **List/View**: `@request.auth.id != ""` (Any authenticated user can view profiles).
-   **Create**: `@request.auth.id != ""` (Allow creation on first sign-in).
-   **Update/Delete**: `id = @request.auth.id` (Only the user can update their own profile).

### 2. `groups`
-   **List/View**: `@request.auth.id != ""` (Any authenticated user can view public groups).
-   **Create**: `@request.auth.id != ""` and `@request.data.ownerId = @request.auth.id` (Enforce creator as owner).
-   **Update**: `ownerId = @request.auth.id` (Only owner can update group details).
-   **Delete**: `ownerId = @request.auth.id` (Only owner can delete).

### 3. `group_members`
-   **List/View**: `@request.auth.id != ""`
-   **Create**: `@request.auth.id != ""` and `@request.data.userId = @request.auth.id` (Users can only add themselves to a group).
-   **Update/Delete**: `@request.auth.id = userId` or `@request.auth.id = groupId.ownerId` (User can leave, or group owner can remove members).

### 4. `friends`
-   **List/View**: `@request.auth.id = requesterId || @request.auth.id = receiverId` (Only involved parties can see the relationship).
-   **Create**: `@request.auth.id = requesterId` (User can only send requests claiming to be themselves).
-   **Update/Delete**: `@request.auth.id = requesterId || @request.auth.id = receiverId` (Either party can accept or remove).
